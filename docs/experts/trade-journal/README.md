# Trade Journal — MT5 EA 1.20

EA สำหรับ **บันทึกรายละเอียดการเทรดทั้งบัญชีลง CSV** เพื่อให้ผู้ใช้วิเคราะห์ย้อนหลังเอง ไม่มีสัญญาณเข้า ไม่มีการให้คะแนนกลยุทธ์ ไม่มีการส่งคำสั่งหรือแก้ไขออเดอร์ และไม่มีการส่งข้อมูลออกอินเทอร์เน็ตจาก EA

บันทึกทุก symbol รวมการเทรดผ่านหน้าจอ MT5, มือถือ/เว็บที่เข้าบัญชีเดียวกัน และ EA ทุก magic number จึงรวมไม้ที่ผู้ใช้กดผ่าน **Scalp Calculator / Instant Engulf** โดยไม่ต้องแก้ EA เดิม ไม่กรองเฉพาะ `magic=0` เพราะปุ่ม Calculator ส่งคำสั่งผ่านโปรแกรม

## ติดตั้งคู่กับ Calculator Panel

1. แตก `TradeJournal-1.20.zip`
2. ใน MT5 เลือก **File → Open Data Folder**
3. คัดลอกโฟลเดอร์ `MQL5/Experts/TradeJournal` จาก ZIP ไปที่ `MQL5/Experts` ใน Data Folder
4. Navigator → Expert Advisors → คลิกขวา **Refresh**
5. คัดลอกโฟลเดอร์ `MQL5/Scripts/TradeJournal` จาก ZIP ไปที่ `MQL5/Scripts` ด้วย เพื่อใช้ตัวส่งออกรายงาน HTML
6. **เปิดกราฟอีกหน้าต่าง** แล้วลาก TradeJournal ลงไป จะใช้ symbol/TF ใดก็ได้ เพราะบันทึกทั้งบัญชี
7. คง Scalp Calculator บนกราฟเทรดเดิม แล้วเทรดตามปกติ ไม่ใส่ Journal ทับกราฟ Calculator เพราะ MT5 ใส่ EA ได้หนึ่งตัวต่อกราฟ
8. ตรวจข้อความบนกราฟ Journal ว่า `RECORDING` และตรวจว่ามี CSV ในตำแหน่งด้านล่าง ช่วงแรกจะแสดง history loading

Journal ไม่ต้องใช้ DLL หรือ WebRequest และไม่มีคำสั่งเทรด จึงไม่ต้องอนุญาตการเทรดให้ Journal; ปุ่ม Algo Trading/สิทธิ์เทรดของ Calculator ยังต้องตั้งตามการใช้งาน Calculator ตามเดิม ต้องเปิด terminal ให้ทำงานและเชื่อมต่อบัญชีเพื่อรับเหตุการณ์ใหม่ รวมถึงกรณีกดเทรดจากมือถือ

ติด Journal **เพียงหนึ่งกราฟต่อบัญชีใน terminal นี้** ตัวที่สองจะถูกปฏิเสธด้วย file lock เพื่อไม่ให้เขียนไฟล์ซ้ำ หากใช้หลาย MT5 terminal แต่ละ terminal มี Data Folder และ journal ของตนเอง ไม่ควรนำ CSV ของหลาย terminal มารวมแล้วนับซ้ำโดยไม่ใช้ deal ticket

## เปิดไฟล์บันทึก

**File → Open Data Folder → MQL5 → Files → TradeJournal → โฟลเดอร์บัญชี**

ชื่อโฟลเดอร์คือ `<account_login>_<server_encoded>` โดย server_encoded เป็น UTF-16 hex ของชื่อ server เพื่อแยกบัญชีเลขเดียวกันคนละ broker/server อย่างแน่นอน ชื่อ server ที่อ่านได้อยู่ในทุก CSV และบนกราฟ Journal ตำแหน่งเต็มพิมพ์ใน Experts log ตอนเริ่มทำงาน

| ไฟล์ | เนื้อหา |
|---|---|
| `deals.csv` | แต่ละ execution/deal: เวลาและราคา fill จริง, Buy/Sell, เปิด/ปิด/กลับฝั่ง/close-by, lot, SL/TP ตาม history, profit, commission, swap, fee, net, symbol, ticket, order, position ID, magic และ reason |
| `events.csv` | เหตุการณ์สดของคำสั่ง/deal/SL/TP และ snapshot ของ positions กับ pending orders ที่ยังเปิด รวมการเพิ่ม/ลด volume และสถานะที่ไม่เปิดอยู่อีกต่อไป |
| `sessions.csv` | เริ่ม/หยุดบันทึก เชื่อมต่อ/ขาดการเชื่อมต่อ ผลสแกน history และ heartbeat ทุกประมาณ 60 วินาที ใช้ดูช่วงที่อาจมีข้อมูลขาด |
| `writer.lock` | ไฟล์ล็อกผู้เขียน ไม่มีข้อมูลการเทรด ไม่ต้องแก้ไขหรือลบขณะ EA ทำงาน |

CSV เป็น **UTF-8, comma delimiter, decimal point `.`** ทุกช่องข้อมูลมี double quotes ข้อความขึ้นบรรทัดใหม่เปลี่ยนเป็น `\r` / `\n` เพื่อให้หนึ่ง record อยู่หนึ่งบรรทัดจริง ข้อความที่อาจเป็นสูตร spreadsheet จะเติม apostrophe ด้านหน้า ส่วนตัวเลขติดลบยังเป็นตัวเลขตามปกติ

แนะนำ **คัดลอก CSV ไปอีกที่ก่อนเปิดวิเคราะห์** และใช้ Excel → Data → From Text/CSV เลือก UTF-8 / comma ตั้งคอลัมน์ ticket, position ID, magic และ account_login เป็น **Text** เพื่อไม่ให้ Excel ปัดเลขยาวเกิน 15 หลัก อย่าบันทึกทับไฟล์ที่ EA กำลังใช้งาน

## อ่าน deals.csv

- หนึ่ง deal ไม่จำเป็นต้องเท่ากับหนึ่งไม้ที่ผู้ใช้คิดไว้: การเปิด/ปิดบางส่วนหรือ partial fill อาจมีหลาย deals ใช้ `position_id` เชื่อมรายการที่เกี่ยวข้อง และ `order_ticket` เชื่อม executions ของคำสั่งเดียวกัน
- Hedging แยก position ID ต่อ position; Netting อาจเพิ่ม/ลด/กลับทิศใน position ID เดิม ใช้ `entry` (`DEAL_ENTRY_IN`, `OUT`, `INOUT`, `OUT_BY`) และชนิด deal ตามที่ broker รายงาน ไม่สร้างคู่เข้าออกปลอม
- **Sell deal อาจเป็นการปิด Buy** จึงต้องอ่าน `entry` ร่วมกับ `deal_type` ไม่ดู Buy/Sell เพียงอย่างเดียว
- `deal_time_msc` เป็นเวลาที่ broker บันทึก deal ละเอียดระดับ millisecond; `deal_time` เป็นรูปแบบวันที่เวลาเดียวกันที่อ่านง่าย ใช้เวลาของ broker ไม่แปลงเป็นเวลาไทย
- `recorded_server_time` เป็นเวลาที่ Journal เขียน record อาจช้ากว่า deal มากเมื่อดึงย้อนหลัง
- `sl` / `tp` มาจาก `DEAL_SL` / `DEAL_TP`: deal เข้าอิง order ที่ใช้เข้า, deal ออกอิง position ตอนออก ไม่ใช่แผน SL/TP เริ่มต้นตลอดอายุไม้
- `net = profit + commission + swap + fee` ตามข้อมูล deal นั้นในสกุลเงินบัญชี ไม่มีการประมาณค่าเพิ่ม หาก broker แยกค่าธรรมเนียมเป็น deal ต่างหากก็เก็บแยกไว้
- เก็บ balance/credit/commission และรายการอื่นของ broker ด้วย แยกด้วย `deal_type`; `position_id=0` หมายถึงไม่มี linkage ที่ broker ให้ ไม่ถือว่าทุกรายการเป็นกำไรจากเทรด
- `reason` คือแหล่ง/เหตุของ deal ตาม MT5 เช่น CLIENT, MOBILE, WEB, EXPERT, SL, TP ไม่ใช่การเดาว่าใครกดแก้ไขก่อนหน้านั้น; ออเดอร์จาก Calculator แสดง EXPERT พร้อม magic ของเครื่องมือ

### ป้องกันซ้ำและรายการแก้ไข

ปกติแต่ละ `deal_ticket` มีหนึ่งแถว `action=UPSERT`, `revision=1` การรีสตาร์ตหรือ scan ซ้ำไม่เพิ่มแถวเดิม หาก broker เปลี่ยนข้อมูล deal เดิม จะเพิ่มแถว revision ถัดไป; หากได้รับเหตุการณ์ลบ จะเพิ่ม `action=DELETE` แทนการลบหลักฐานเก่า

**ก่อนรวมกำไร ให้เลือก revision สูงสุดของแต่ละ deal_ticket แล้วตัดรายการที่ action=DELETE ออก** ห้ามรวมทุก revision เพราะจะนับรายการแก้ไขซ้ำ DELETE เก็บค่าเดิมไว้เพื่อ audit; หากไม่เคยอ่าน deal นั้นได้จะมีเฉพาะ identity และช่องอื่นว่าง

`origin` แยก HISTORY_BACKFILL, HISTORY_RECONCILE, TRANSACTION_OR_RETRY และ LIVE_DELETE เป็นแหล่งที่ Recorder อ่านข้อมูล ไม่ใช่ช่องทางที่ผู้ใช้ส่งออเดอร์ ช่องทางจริงดู `reason` / `magic`

## อ่าน events.csv

- `LIVE_TRANSACTION` บันทึกค่าจาก transaction ที่ terminal ได้รับไว้ใน queue ก่อนเขียนไฟล์ จึงเก็บการขยับ SL/TP หลายครั้งที่เกิดก่อน timer รอบถัดไปได้ตาม events ที่ได้รับ
- `OBSERVED_SNAPSHOT` เก็บสถานะที่อ่านได้ในรอบ timer: `POSITION_BASELINE` / `ORDER_BASELINE` คือสถานะเมื่อเริ่มหรือเชื่อมต่อใหม่, `FIRST_OBSERVED` คือพบครั้งแรกใน session, `CHANGED` คือแตกต่างจาก snapshot ก่อนหน้า
- BASELINE/FIRST_OBSERVED เป็น **ค่าแรกที่ Journal เห็น** ไม่ยืนยันว่าเป็นค่าเมื่อเปิด position จริง เพราะอาจแนบ Journal หลังเข้าไม้แล้ว
- `POSITION_NO_LONGER_OPEN` / `ORDER_NO_LONGER_ACTIVE` ใช้ `LAST_OBSERVED_SNAPSHOT` และค่าที่เห็นครั้งสุดท้าย ไม่ใช่ราคา fill ตอนปิด และไม่ได้ยืนยันสาเหตุที่หายไป ราคา/volume ปิดจริงให้อ่าน deals.csv
- `position_ticket` ของ transaction อาจต่างจาก `position_id` ที่คงที่ โดยเฉพาะ Netting reversal หรือ broker service operations ไม่ใช้สองค่านี้แทนกัน
- Metadata ที่ transaction ไม่มี เช่น magic/reason/position ID จะว่าง ไม่หยิบสถานะปัจจุบันมาสวมให้เหตุการณ์ในอดีต ให้อ่าน deal หรือ snapshot ที่เกี่ยวข้องแทน
- `observed_server_time` และ `observed_local_time` คือเวลาที่ Recorder รับรู้เหตุการณ์ (ละเอียดวินาที) ไม่ใช่เวลาที่คุณคลิกแน่นอน; `sequence` ภายใน `session_id` เป็นลำดับที่ Recorder ได้รับ ไม่รับประกันลำดับเหตุการณ์ต้นทางจาก broker
- Volume ของ ORDER transaction คือส่วนที่ยังไม่ fill; volume ของ DEAL คือส่วนที่ fill; snapshot position คือขนาด position ณ ตอนที่อ่าน
- เหตุการณ์ Request/retcode ที่ยังไม่เป็น execution ไม่ถูกนับเป็น deal

## Inputs

| Input | ค่าเริ่มต้น | ความหมาย |
|---|---:|---|
| `InpHistoryDays` | 0 | ตอนเริ่ม/เชื่อมต่อใหม่ สแกน deal history ทั้งหมดที่ broker ให้; ตั้งจำนวนวันเพื่อจำกัดได้ 1–36500 ไม่มีการลบ CSV เดิมเมื่อเปลี่ยนค่า |
| `InpReconcileSeconds` | 30 | สแกน history ซ้ำตามช่วงเวลา พร้อม overlap 120 วินาทีเพื่อเก็บรายการที่มาช้า; ตั้งได้ 5–3600 |
| `InpShowStatus` | true | แสดงสถานะและตำแหน่งไฟล์บนกราฟ Journal |

Timer ทำงานทุก 1 วินาที โดย snapshot เฉพาะส่วนที่เปลี่ยนและอ่าน history ทีละไม่เกิน 200 tickets ต่อรอบ งานซ้ำจาก event/history จะตรวจ ticket + เนื้อหาก่อนบันทึก เมื่อ history ของ deal ยังไม่พร้อมจะเก็บ retry และแสดงจำนวนบนกราฟ

## ช่วงข้อมูลขาดและการกู้คืน

- หลังเริ่มใหม่ สร้าง index กันซ้ำจาก deals.csv แล้วดึง **รายการซื้อขายจริงที่ยังมีใน history ของ broker** กลับมา ค่าเริ่มต้นดึงทั้งหมด หากจำกัดจำนวนวันจะไม่กู้รายการก่อนช่วงนั้น
- การปิด MT5, คอม sleep, เน็ตหลุด หรือถอด EA ทำให้ขาดภาพเหตุการณ์สด ไม่สามารถกู้ลำดับ SL/TP ทุกครั้ง, pending order ที่สร้างและยกเลิกหมดระหว่าง offline หรือเวลาคลิกจริงจาก deal history ได้
- Broker อาจจำกัด/แก้/ลบ history: ไม่ถือว่า deal ที่หายจาก history ระหว่าง offline ถูกลบโดยอัตโนมัติ บันทึก DELETE เฉพาะเมื่อ terminal ส่งเหตุการณ์ลบมาให้
- การ crash อาจไม่มี STOP ใน sessions.csv; ใช้ heartbeat ล่าสุดช่วยระบุขอบเขตที่บันทึกได้ ไม่ใช่หลักฐานว่าไม่มี trade หลัง heartbeat
- ระบบเขียนและ flush ทุกแถว แต่ disk failure/crash อาจทำให้แถวท้ายเสียหาย หากพบ schema/แถวผิดรูปหรือเขียนไฟล์ไม่ได้จะ **หยุดบันทึกและแจ้ง STOPPED/Alert** แทนการเขียนทับหรืออ้างว่าข้อมูลครบ ให้สำรองไฟล์และตรวจแก้ไฟล์ที่เสียก่อนแนบใหม่
- ถ้าต้องเริ่มใหม่โดยเก็บหลักฐานเดิม: ถอด Journal, ย้ายโฟลเดอร์บัญชีเดิมไปสำรอง, แล้วแนบใหม่ จะ backfill deals ตาม Inputs แต่ events เก่าอยู่เฉพาะในสำรอง ต้องจัดการ deal ซ้ำหากนำข้อมูลสองชุดมารวม
- ขณะเปลี่ยนบัญชี EA ตรวจ account/server ก่อนบันทึก ถ้าพบว่าไม่ตรงจะหยุดและให้แนบใหม่ เพื่อไม่ปนข้อมูลคนละบัญชี
- Native MT5 transaction queue มีขนาดจำกัด; EA ลดงานใน handler ด้วย queue ภายใน 8192 รายการ หาก queue ภายในเต็มจะหยุดพร้อมแจ้ง coverage gap ไม่รับรองความครบเมื่อเครื่อง/terminal ประมวลผลไม่ทัน

เวอร์ชันนี้ไม่เก็บภาพหน้าจอ ไม่อ่านกลยุทธ์ และไม่คำนวณ R หรือ MAE/MFE ตัวส่งออก HTML ใช้ TF ที่ผู้ใช้เลือกเพื่อดูบริบท ไม่อ้างว่าเป็น TF ที่ใช้ตัดสินใจจริง เพราะ MT5 order ไม่มีข้อมูลนี้ การเปลี่ยน TF ของกราฟ Journal ไม่เปลี่ยนขอบเขตการบันทึกทั้งบัญชี

## รายงาน HTML พร้อมกราฟแท่งเทียน — ใหม่ใน 1.10

ใช้ **ExportJournalReport** ซึ่งเป็น Script แยกจาก EA ตัวบันทึก จึงสร้างรายงานเมื่ออยากทบทวนได้ โดย Journal บันทึกต่อใน thread ของตัวเอง ไม่ต้องใช้ Python, Node, web server, DLL หรือ API key บนเครื่องที่จะเปิดรายงาน

### สร้างและเปิดรายงาน

1. ให้ TradeJournal บันทึกข้อมูลไว้ก่อน หรือใช้ CSV เดิมจากเวอร์ชัน 1.00 ได้ schema ของ CSV ไม่เปลี่ยน
2. ใน Navigator → **Scripts → TradeJournal → ExportJournalReport** (Refresh หากยังไม่แสดง)
3. ลาก Script ลงกราฟว่างสำหรับส่งออกรายงาน ตั้งค่า Inputs แล้วกด OK ตัวส่งออกอ่านบัญชีที่ terminal ล็อกอินอยู่
4. ค่าเริ่มต้นใช้ **M1, M5, M15**, เก็บ **100 แท่งก่อน deal แรก + ทุกแท่งระหว่างช่วงที่บันทึก + 30 แท่งหลัง deal สุดท้าย** ต่อ position; หากยังเปิดอยู่ ใช้เวลาปัจจุบันแทนปลายช่วง
5. รอ Alert `Report ready` ดูความคืบหน้าใน Experts log หาก history มากอาจใช้เวลา และ MT5 อาจดาวน์โหลด history จาก broker ระหว่างนี้
6. ไปที่ Data Folder → MQL5 → Files → TradeJournal → โฟลเดอร์บัญชี → **journal.html** เปิดด้วย browser บนเครื่อง
7. เลือก **เปิด / แก้บันทึก** จากหน้า list หรือเลือก position ทางซ้าย เปลี่ยน TF, ซูม/ลากกราฟ, เปิดปิด SL/TP และดูตาราง executions/เหตุการณ์ด้านล่าง
8. ปุ่ม **บันทึก HTML ของรายการนี้** ดาวน์โหลดรายงานแยก position พร้อมกราฟของรายการนั้น รวมบันทึกส่วนตัวของรายการนั้น โดยไม่ฝัง deals/charts/notes ของ positions อื่น เก็บ session coverage ของบัญชีไว้เป็นบริบท

**รายงานไม่อัปเดตอัตโนมัติหลังเปิด** ให้รัน Script ใหม่แล้วเปิด/Reload HTML เมื่อต้องการข้อมูลล่าสุด และคัดลอก HTML ไปเก็บชื่ออื่นก่อนส่งออกครั้งใหม่หากต้องการรักษา snapshot เก่า

ไฟล์เดียวฝัง HTML/CSS/JavaScript, CSV ที่อ่านในรอบนั้น และ OHLC/volume/spread ของแท่งเทียนไว้ครบ ไม่มี CDN หรือการโหลดไฟล์ข้างเคียง จึงนำ HTML ไปเปิดบนอีกเครื่องแบบออฟไลน์ได้ ไม่ต้องนำ CSV ติดไปด้วย

มี [ตัวอย่างรายงานจากข้อมูลสาธิต](journal-demo.html) สำหรับลองหน้าตา ไม่ใช่ข้อมูลบัญชีจริง

### Inputs ของ ExportJournalReport

| Input | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `InpReportTimeframes` | `M1,M5,M15` | เลือกได้ 1–8 TF คั่นด้วย comma; รองรับ TF มาตรฐาน MT5 ตั้งแต่ M1 ถึง MN1 ไม่ใช้ TF ของกราฟที่ลาก Script ลงไปโดยอัตโนมัติ |
| `InpBarsBefore` | 100 | แท่งก่อน deal แรกที่บันทึกใน position; ตั้งได้ 0–5000 |
| `InpBarsAfter` | 30 | แท่งหลัง deal สุดท้ายที่บันทึก; ตั้งได้ 0–5000 มีได้เท่าที่เกิดขึ้นจริงแล้ว |
| `InpMaxBarsPerChart` | 10000 | เพดาน 100–100000 แท่งต่อ position/TF ถ้าเกินจะไม่ตัดช่วงทิ้งเงียบ ๆ แต่ให้เลือก TF ใหญ่ขึ้นหรือเพิ่มเพดาน |
| `InpMaxPositions` | 0 | 0 = ทุก position ใน CSV; ค่ามากกว่า 0 เก็บกราฟเฉพาะจำนวน positions ที่มีรายการล่าสุดตามที่กำหนด รายการอื่นยังอยู่ในตารางเลือกแต่ไม่มีกราฟ |

### ความหมายและข้อจำกัดของกราฟ

- กราฟสร้างจาก **history ของ broker ณ เวลา export** ไม่ใช่ภาพหรือ snapshots ของ indicators ตอนคุณคลิกซื้อขาย หาก broker แก้ history ภายหลัง ส่งออกรอบใหม่อาจได้ OHLC ต่างจากไฟล์เก่า
- แต่ละแท่งฝังเวลาเปิด, OHLC, tick volume, real volume, spread เป็น points และสถานะว่าปิดแล้วหรือยังที่ตรวจจาก series ในตอน export แท่งที่ยังไม่ยืนยันว่าปิดจะโปร่งกว่าปกติ
- ไม่สร้างแท่งเทียนเติมเอง หาก symbol/history ไม่พร้อม, ประวัติถูกจำกัด, หลังออกยังมีแท่งไม่ครบ หรือช่วงถือยาวเกินเพดาน จะแสดงสถานะชัดเจน ลองรันใหม่เมื่อโหลด history พร้อม เพิ่ม Max bars in chart ของ MT5 หรือเลือก TF ใหญ่ขึ้นตามกรณี
- ราคาแท่งเทียนอาจเป็น Bid/Last แต่ execution/SL/TP อาจอิงอีกด้านของ quote จึงไม่ควรสรุปว่า fill ผิดจากการเห็น marker อยู่นอก wick เพียงอย่างเดียว
- เส้น SL/TP เริ่มที่เวลาที่มีหลักฐานจาก deal/event/snapshot ไม่เอาค่าสุดท้ายลากย้อนหลังตั้งแต่เปิดไม้ และไม่ใช้ `NO_LONGER_OPEN` เป็นราคาปิดจริง
- OHLC ไม่มีลำดับ ticks ภายในแท่ง กราฟจึงไม่ได้พิสูจน์ว่าแตะ SL/TP อะไรก่อนด้วยตัวแท่งเอง จุด executions ใช้เวลาและราคา fill ที่บันทึกใน deals
- TF ทั้งสามเป็นมุมมองบริบท ไม่ยืนยันว่าไม้ถูกตัดสินใจบน TF ใด และไม่วาด MACD, PA, swing หรือเส้นที่ผู้ใช้วาดบน MT5 ขึ้นใหม่
- รายงานจัดกลุ่มตาม **position ID**; Netting ที่เพิ่ม/ลด/กลับฝั่งใน ID เดิมยังอยู่กลุ่มเดียว ไม่อ้างว่าหนึ่งกลุ่มเท่ากับหนึ่ง setup ทางกลยุทธ์ หากประวัติไม่เริ่มด้วย deal เปิด จะแจ้งว่าประวัติเริ่มต้นไม่ครบ
- เลือก revision ล่าสุด ตัด DELETE ก่อนรวมผลสุทธิ รวมค่าธรรมเนียมที่ broker เชื่อม position ได้; ค่าธรรมเนียม/เงินเข้าออกที่ไม่เชื่อม position ไม่ถูกยัดให้ไม้ใด รายงานไม่รวม floating P/L
- CSV แต่ละไฟล์ถูกอ่านเป็น snapshot แยกกัน ขณะเทรดต่ออาจมีเหตุการณ์ใหม่หลังจากอ่าน deals ไปแล้ว เหตุการณ์ที่เชื่อมไม่ได้เก็บในส่วนข้อมูลประกอบ ไม่เดาว่า position ticket เท่ากับ position ID
- หาก Script อ่านไฟล์ในจังหวะเขียนไม่ครบ/พบ schema ผิด จะหยุดและให้ลองใหม่ ไม่มีการแก้ CSV ต้นฉบับ รายงานใหม่เขียนลง temporary file ก่อน แล้วจึงแทน `journal.html` เมื่อสำเร็จ ตัวส่งออกใช้ `report.lock` แยกจาก `writer.lock`

## หน้า list และบันทึกส่วนตัว — ใหม่ใน 1.20

รายงานเปิดที่ **รายการ Journal** มีช่องค้นหา Symbol, Position ID, Setup, Tags และเหตุผลก่อน/หลังเข้า พร้อมตัวกรอง **ยังไม่รีวิว / กำลังรีวิว / รีวิวแล้ว** คลิก **เปิด / แก้บันทึก** เพื่อดูกราฟและกรอกบันทึกของ position นั้น แล้วใช้ **กลับรายการ Journal** เลือกไม้ถัดไป

บันทึกได้:

- Setup / กลยุทธ์, Tags, ความมั่นใจก่อนเข้า 1–5 และสถานะรีวิว
- เช็กลิสต์ที่แก้ข้อความ เพิ่ม ลบ และติ๊กได้แยกต่อไม้ ข้อเริ่มต้นเป็นตัวอย่าง ไม่ใช่การตัดสินว่ากลยุทธ์ผ่านหรือไม่
- อารมณ์ก่อนเข้า ระหว่างถือ และหลังออก เป็นข้อความอิสระ
- เหตุผลและบริบทก่อนเข้า การตัดสินใจระหว่างถือ เหตุผลหลังออก บทเรียน ข้อผิดพลาด และสิ่งที่จะทำครั้งหน้า

รายการซื้อขาย ราคา กำไร และกราฟยังมาจาก EA ตามเดิม การแก้โน้ตไม่แก้ CSV และไม่มีระบบวิเคราะห์/ให้คะแนนอัตโนมัติ โน้ตจัดกลุ่มตาม position ID เช่นเดียวกับกราฟ จึงรวมการเพิ่มไม้/ปิดบางส่วน และอาจรวมการกลับฝั่งในบัญชี Netting

### การเซฟและการส่งออกรอบใหม่

**HTML เซฟการแก้ไขลง localStorage ของ browser โดยอัตโนมัติ แต่เขียนทับไฟล์ HTML ต้นฉบับหรือ CSV ไม่ได้** บันทึกแยกด้วยบัญชี + server + position ID และแยกข้อมูลสาธิตจากข้อมูลจริง แม้ส่งออกข้อมูลเทรดรอบใหม่ ID เดิมยังเชื่อมกับโน้ตเดิมได้ หาก browser เปิดไฟล์ใน storage เดิม

การเปิด `file://` มีพฤติกรรม storage ต่างกันตาม browser/ที่อยู่ไฟล์ การย้ายหรือเปลี่ยนชื่อ HTML, เปลี่ยน browser/เครื่อง, private mode หรือเคลียร์ browser data อาจทำให้โน้ตไม่ปรากฏ จึงมีวิธีเก็บถาวรด้วยไฟล์:

1. **สำรองบันทึก JSON** เก็บเฉพาะบันทึกส่วนตัวของ positions ในรายงานปัจจุบัน เหมาะสำหรับย้ายเข้า `journal.html` รอบใหม่ ไม่ได้เก็บแท่งเทียนหรือ trade history
2. **ดาวน์โหลด HTML พร้อมบันทึกทั้งหมด** เก็บ snapshot ข้อมูลเทรด กราฟ และโน้ตของรายงานนี้ในไฟล์เดียว เปิดอีกเครื่องแบบออฟไลน์ได้
3. **บันทึก HTML ของรายการนี้** เก็บเฉพาะ position ที่เลือกพร้อมโน้ตและกราฟ; session coverage ของบัญชียังอยู่เป็นบริบท
4. เมื่อเปิดรายงานใหม่แล้วไม่เห็นโน้ต ให้กด **นำเข้าบันทึก JSON** เลือกไฟล์สำรอง ตรวจจำนวนรายการ แล้วกด **นำเข้าตามตัวเลือก** ระบบรับเฉพาะบัญชี/server/demo flag และ positions ที่อยู่ในรายงานนี้ รายการอื่นถูกข้ามและยังอยู่ในไฟล์สำรอง
5. ค่าเริ่มต้นของการนำเข้า **เก็บโน้ตเดิม** และเติมเฉพาะไม้ที่ยังไม่มี หากต้องการใช้ฉบับใน JSON ทับของเดิม ให้สำรองฉบับปัจจุบันก่อน แล้วติ๊ก **แทนที่บันทึกเดิมด้วยข้อมูลในไฟล์นี้**

ตรวจ Downloads หลังดาวน์โหลดและเก็บสำรองไว้เอง Browser อาจเปลี่ยนชื่อไฟล์แทนการทับไฟล์เดิม HTML ที่ส่งออกใหม่จาก MT5 ไม่อ่านโน้ตใน browser กลับไปฝังโดยอัตโนมัติ ต้องดาวน์โหลด HTML พร้อมบันทึกจากหน้ารายงานหากต้องการไฟล์พกพาที่รวมโน้ตล่าสุด

เวลาแก้ไขโน้ตใช้เวลาของเครื่อง ส่วนกราฟและเวลา deal ใช้เวลา broker ช่องก่อน/ระหว่าง/หลังเข้าแก้ย้อนหลังได้ จึงไม่ยืนยันว่าผู้ใช้เขียน ณ จังหวะนั้น เมื่อ HTML มีโน้ตฝังอยู่และ browser มีโน้ตของไม้เดียวกัน ระบบเลือกฉบับที่มีเวลาแก้ไขล่าสุดตามนาฬิกาเครื่อง หากต้องการเลือกอีกฉบับ ให้ใช้การนำเข้า JSON แบบแทนที่

หาก storage ใช้ไม่ได้/เต็มหรือพบว่าหน้าต่างอื่นแก้ค่าที่โหลดไว้ ระบบแจ้งว่า **ยังไม่เซฟลง browser** และเก็บฉบับที่กำลังพิมพ์ในหน้านี้ไว้ การสลับไปดูไม้อื่นไม่ทิ้ง draft ให้สำรอง JSON หรือดาวน์โหลด HTML ก่อนปิด/Reload หน้ารายงาน ข้อมูล storage ที่เสียหายจะไม่ถูกเขียนทับโดยอัตโนมัติ

ขอบเขต: สูงสุด 30,000 ตัวอักษรต่อช่อง และเช็กลิสต์ 100 ข้อ (500 ตัวอักษรต่อข้อ); นำเข้า JSON ไม่เกิน 10 MB ไม่มี cloud sync, การแนบรูป หรือเทมเพลตเช็กลิสต์ส่วนกลางในรุ่นนี้ การบันทึกเทรดของ EA เป็นอัตโนมัติ แต่การเพิ่ม trades/แท่งเทียนล่าสุดเข้า HTML ยังต้องรัน ExportJournalReport ตามขั้นตอนเดิม
