# WickHuntAnchor 1.12

Indicator MT5 สำหรับ **TF ใหญ่ wick hunt → Close TF ย่อยยืนยันกลับถึง Open → แท่งแรกที่ปลายหางลากไปชนทางซ้ายเป็น FVG หรือแท่งหางหัวสั้น** ค่าเริ่มต้น **H1 / M5 ตรวจทุกครั้งที่ M5 ปิด** ไม่ใช้ MACD, S/R, Breakout/Pullback, เทรนด์ หรือการ breakout/hold/retest ของ TF ย่อย ไม่เปิดออเดอร์ เป็นคนละตัวกับ WickHuntSRFlow และไม่เปลี่ยน WickHuntTelegramEA

ค่าเริ่มต้น `InpHuntTF=PERIOD_H1`, `InpCheckTF=PERIOD_M5`, `InpObservationMode=WHA_LOWER_TF_CLOSE` ตรวจ hunt และ anchor บน H1 โดยใช้ Close M5 ยืนยันการกลับถึง Open H1 แล้วให้สัญญาณในรอบตรวจนั้น ไม่ต้องรอ H1 ปิด ทั้งสอง TF ปรับได้จาก Inputs และไม่เปลี่ยนตาม TF ของกราฟที่เปิดดู

มีเวอร์ชัน **TradingView Pine Script v6 รุ่น 1.05** ซึ่งใช้เงื่อนไขราคาเดียวกับ MT5 1.12 ในโหมด TF ย่อยปิด รวมตัวกรองหางเดิม/เนื้อแท่ง: [source](../../../Pine/Indicators/WickHuntAnchor.pine) และ [วิธีติดตั้ง / Inputs / Alerts](pine.md)

## กฎ Buy / Sell

| เงื่อนไข | Buy | Sell |
|---|---|---|
| Hunt | Low ปัจจุบันต่ำกว่า Low ต่ำสุดของ N แท่งหลักก่อนหน้า และต่ำกว่า Open ของตัวเอง | High ปัจจุบันสูงกว่า High สูงสุดของ N แท่งหลักก่อนหน้า และสูงกว่า Open ของตัวเอง |
| กลับถึง Open ในโหมดค่าเริ่มต้น | Close M5 ≥ Open H1 | Close M5 ≤ Open H1 |
| ปลายหาง | Low ของแท่ง hunt ณ ตรวจพบ | High ของแท่ง hunt ณ ตรวจพบ |
| แท่งแรกที่ชน | ไล่แท่งหลักที่ปิดแล้วจากใกล้ไปไกล หยุดที่แท่งแรกซึ่ง Low ≤ ปลายหาง ≤ High | เช่นเดียวกัน |
| ความแรงของแท่งที่ชน | `(High − max(Open, Close)) / (High − Low) × 100 < 30%` | `(min(Open, Close) − Low) / (High − Low) × 100 < 30%` |

จำนวนหาง `InpHuntBars=1` เป็นค่าเริ่มต้น ถ้าตั้ง N มากขึ้นต้องกวาดขอบสุดของ **ทุกแท่ง** ในช่วงนั้นในแท่ง hunt เดียว ไม่รวมแท่งปัจจุบัน Hunt ต้องทะลุจริง; แตะหางเดิมพอดีไม่ผ่าน การกลับถึง Open พอดีผ่าน

## หางที่ถูกกวาดเทียบกับเนื้อแท่ง — ใหม่ใน 1.10

`InpMinSweptWickBodyPercent=10` กำหนดเปอร์เซ็นต์ขั้นต่ำ **เฉพาะเมื่อ `InpHuntBars=1`** ตรวจแท่ง TF หลักก่อนหน้า ซึ่งเป็นแท่งที่ถูกกวาด ไม่ใช่แท่ง hunt ปัจจุบันหรือแท่ง anchor

- Buy: `(min(Open, Close) − Low) / abs(Close − Open) × 100`
- Sell: `(High − max(Open, Close)) / abs(Close − Open) × 100`
- ต่ำกว่าเกณฑ์ไม่ผ่าน; เท่ากับเกณฑ์ผ่าน เช่น เนื้อ 100 หาง 9 ไม่ผ่าน 10%; หาง 10 ผ่าน
- Doji (`Open=Close`): ผ่านได้หากมีหางด้านที่ถูกกวาด ถ้าไม่มีหางด้านนั้นไม่ผ่านเมื่อเปิดตัวกรอง
- ตั้ง `0` ปิดตัวกรอง; รับค่าไม่ติดลบและตั้งเกิน 100% ได้ เพราะใช้เนื้อแท่งเป็นตัวหาร
- หาก `InpHuntBars≥2` ตัวกรองนี้ไม่มีผล ไม่ตรวจเปอร์เซ็นต์ของแต่ละหางในช่วงนั้น
- ใช้กับทุก observation mode และทุกกฎ anchor รวม FVG only; เป็นคุณสมบัติของแท่งที่ถูกกวาด แยกจาก `InpStrongHeadWickPercent` ที่ใช้ตัดสิน Strong ของ anchor เท่านั้น

## First anchor: FVG หรือแท่งแข็งแรง

เลือก `InpAnchorRule` ได้ 4 แบบ (เลข 0/1 เดิมยังคงเดิมสำหรับ preset/iCustom):

| Rule | เงื่อนไขแท่งแรกที่ชน |
|---|---|
| `WHA_FVG_OR_STRONG` (0, ค่าเริ่มต้น) | ผ่าน FVG **หรือ** Strong อย่างใดอย่างหนึ่ง |
| `WHA_FVG_AND_STRONG` (1) | ต้องผ่าน FVG **และ** Strong ทั้งคู่ ตามกฎ AND ที่เลือก |
| `WHA_FVG_ONLY` (2) | ตรวจเฉพาะ FVG ไม่ใช้เกณฑ์หางหัวของ Strong กรอง FVG |
| `WHA_STRONG_ONLY` (3) | ตรวจเฉพาะ Strong ไม่ต้องมี FVG |

- `InpStrongHeadWickPercent` ใช้ตัดสิน **Strong เท่านั้น** เปลี่ยนเป็น 30% เป็นค่าเริ่มต้นใน MT5 v1.03; ใน OR แม้หางหัว ≥30% แต่เป็น FVG ก็ผ่าน ใน FVG only เปอร์เซ็นต์นี้ไม่มีผลต่อการรับ FVG ส่วน AND ต้องผ่าน Strong ด้วยเพราะเป็นเงื่อนไขร่วมที่เลือก
- Strong: หางหัวต้อง **สั้นกว่า** ค่า Input (ค่าเริ่มต้น 30%) ของ High−Low ทั้งแท่ง ไม่ใช่เปอร์เซ็นต์ของเนื้อแท่ง เท่ากับ 30% ไม่ผ่านสาขา Strong
- ตั้งแต่ MT5 v1.05 **Buy ต้องชน anchor แท่งเขียว** (`Close > Open`) เป็นค่าเริ่มต้น ด้วย `InpRequireBuyAnchorGreen=true` เป็นตัวกรองร่วมของ FVG only, Strong only, OR และ AND แท่งแดงหรือ Doji ที่เป็นแท่งแรกจะทำให้ Buy ไม่ผ่าน แม้เป็น FVG/Strong และไม่ข้ามไปหาแท่งเขียวที่อยู่ไกลกว่า
- สีที่ตรวจคือแท่งที่ปลายหางชนจริง ไม่ใช่สีของแท่ง hunt หรือแท่งอื่นในชุด FVG หากชนแท่งกลาง FVG ตรวจสีแท่งกลาง; หากชนแท่งที่ 3 ตรวจสีแท่งที่ 3
- ตั้งแต่ MT5 v1.07 **Sell ต้องชน anchor แท่งแดง** (`Close < Open`) เป็นค่าเริ่มต้น ด้วย `InpRequireSellAnchorRed=true` ใช้ร่วมกับ FVG only, Strong only, OR และ AND แท่งเขียวหรือ Doji ที่เป็น first collision ไม่ผ่านและไม่ข้ามไปหาแท่งแดงที่ไกลกว่า
- Buy/Sell ใช้การทบทวนปลายหางเดียวกัน: หากหางขยายแล้วชนแท่งผิดสี จะลบ event เดิมทั้งลูกศร/เส้น/buffers และรอเงื่อนไขใหม่ ตรวจทุก M5 ปิดในโหมด H1/M5 และทุก tick/timer ในโหมด tick
- `InpRequireAnchorColor=true` เป็นตัวเลือกเดิมที่เปิดกรองสีทั้งสองฝั่งเสมอ หากต้องการปิดเฉพาะฝั่ง ให้ปิด Input ของฝั่งนั้นและปิด `InpRequireAnchorColor` ด้วย
- ตั้งแต่ MT5 v1.08 จำกัดระยะจากแท่ง hunt ถึงแท่ง anchor ด้วย `InpSearchBars=36` เป็นค่าเริ่มต้น ใช้กับ Buy/Sell และทุก Rule ทั้งสร้างสัญญาณและทบทวนเมื่อหางขยาย
- นับเป็นจำนวนแท่งของ **TF หลัก**: แท่งก่อนหน้า = ระยะ 1, ระยะ 36 ยังผ่าน, ระยะ 37 ไม่ผ่าน ไม่ใช่แท่ง TF ย่อยหรือ TF ที่เปิดกราฟ และไม่ใช่จำนวนชั่วโมงตามนาฬิกา ระยะนับถึงแท่ง anchor ที่ชนจริง ไม่ใช่ถึงแท่งยืนยัน FVG
- ตั้ง `InpSearchBars=0` เพื่อปิดการจำกัดระยะ ใช้ประวัติที่โหลดทั้งหมดได้เหมือนเดิม ค่าอื่น 1–100000 กำหนดระยะสูงสุด ไม่ข้าม first collision แม้ค้นได้ไกลกว่า
- ปลายหางแตะส่วนใดของแท่งแรกได้ รวมไส้และขอบ High/Low ไม่ต้องอยู่ใน body
- ถ้าแท่งแรกไม่ผ่าน จะไม่ข้ามสิ่งกีดขวางไปหาแท่งดีที่อยู่ไกลกว่า ถ้ามี invalid OHLC ในช่วงค้นจะไม่ข้ามข้อมูลที่ขาดหาย
- FVG ยืนยันด้วยสามแท่งตาม `FVGCore.mqh` ของ flow เดิม: Bull `Low3 > High1`, Bear `High3 < Low1`; แท่งกลางต้องครอบคลุม gap ไม่ใช้เพียง session gap และไม่มีกฎว่าปลายหางต้องแตะตัว gap zone
- ตั้งแต่ MT5 v1.04 **แท่งกลาง (ที่ 2) ซึ่งสร้าง FVG เป็น anchor ได้** เมื่อแท่งที่ 3 ยืนยันและปิดก่อนแท่ง hunt เปิดแล้ว ยังคงรับแท่งที่ 3 เป็น anchor ตามกฎเดิม แต่ไม่นับแท่งที่ 1 เพียงเพราะอยู่ในชุด FVG
- ตัวอย่างเรียงซ้าย→ขวา: `① → ② แดงยาว → ③ เล็ก → ④ hunt` ถ้าชุด ①②③ ยืนยัน FVG แล้ว ปลายหางของ ④ ชน ② เป็นแท่งแรกได้ และใน FVG only จะไม่ใช้ % Strong กรอง ② หยุดที่แท่งแรกเช่นเดิม
- ตรวจเฉพาะข้อมูลก่อนแท่ง hunt เปิด: ถ้า ③ ยังไม่ปิด หรือ ③ เป็นแท่ง hunt เอง จะยังไม่รับ ② จากชุดนั้น ไม่ใช้การยืนยันจากแท่งอนาคตมาสร้างสัญญาณย้อนหลัง
- ค่าเริ่มต้นรับ FVG ทั้งสองทิศ `InpRequireFVGMiddleDirection=false` ไม่บังคับสีแท่งกลางตามทิศ FVG แต่ Buy ยังตรวจว่า anchor ที่ชนจริงเป็นแท่งเขียว และ FVG ไม่จำเป็นต้องมีหางหัว <30% เพราะเป็นอีกสาขาของ OR หากต้องการจำกัดทิศ FVG ให้ตรง Buy/Sell เปิด `InpRequireFVGDirection`

เมื่อครบเงื่อนไขให้ได้ไม่เกินหนึ่ง event ที่ยังใช้ได้ต่อฝั่งต่อแท่งหลัก ตั้งแต่ v1.06 เมื่อเปิดกรองสีของฝั่งนั้น จะตรวจ anchor ใหม่เมื่อปลายหางที่สังเกตขยาย: หากยังชนแท่งเดิมและผ่านสี/body/FVG/Strong จะอัปเดตปลายหางล่าสุดและ metadata (ตั้งแต่ 1.11 เส้นตรึงที่ signal tip เดิม) หากไม่ผ่านหรือเปลี่ยนแท่ง anchor จะลบ event เดิมทั้งลูกศร/เส้น/buffers แล้วต้องกลับถึง Open และผ่าน anchor ใหม่จึงให้ event ใหม่ได้ แท่งหลักใหม่เริ่มรอบใหม่

ในโหมด H1/M5 การยืนยันและการทบทวนทำทุก M5 ปิด ลูกศรระหว่าง H1 ที่ยังไม่ปิดจึงเปลี่ยนหรือหายได้ เมื่อ replay ย้อนหลังจะประมวลผลการยกเลิกตามลำดับ M5 ด้วย โดยไม่ใช้ High/Low อนาคตก่อนเกิด Popup ที่ส่งไปแล้วไม่สามารถถอนคืนได้ เมื่อปิดตัวกรองสีของทั้งสองฝั่งจะยังใช้พฤติกรรมจำ anchor ณ สัญญาณเดิม

## ตรวจทุก TF ย่อยปิด — ค่าเริ่มต้นใหม่

`WHA_LOWER_TF_CLOSE` ใช้แท่ง M5 ที่ปิดเรียงตามเวลาเพื่อสะสม High/Low ของ H1 ปัจจุบัน ไม่ดึง H/L สุดท้ายของ H1 มาใช้ก่อนมันเกิด ทุก Close M5 ตรวจว่ากวาดหางครบ, กลับถึง Open H1 และผ่าน first anchor ของ H1 ที่ปิดก่อนแท่ง hunt เปิดแล้วหรือไม่ ผ่านเมื่อใดให้ event ณ Close M5 นั้นทันที ไม่รอ M5 break เส้นใด และไม่รอ hold/retest

ทั้งการตรวจสดและย้อนหลังใช้กฎนี้เหมือนกัน ไม่เกินหนึ่งสัญญาณที่ยังผ่านต่อฝั่งต่อ H1 เมื่อปลายหางเปลี่ยนใน M5 ถัดไปและเปิดกรองสี จะตรวจ first anchor ใหม่ตามกฎ v1.06 ข้างต้น แท่ง M5 สุดท้ายที่ปิดตรงจบ H1 ตรวจและยกเลิกสัญญาณของ H1 เดิมได้ ลูกศรผูกกับแท่ง M5 ที่ยืนยัน event ที่ยังผ่าน

ใช้ข้อมูลที่ MT5 โหลดทั้งสอง TF เท่านั้น ตั้งแต่ **1.12** หากแท่งย่อยเริ่มหลังเวลาเปิดแท่งหลัก หรือมีเวลาข้ามระหว่างแท่งย่อย จะตรวจช่วงที่หายกับ **quote sessions ของ symbol จากโบรกเกอร์**:

- ถ้าช่วงที่หายทั้งหมดอยู่นอก quote session เช่น เปิดวันอาทิตย์ช้ากว่าเวลา H4 หรือพักตลาดระหว่าง H4 จะตรวจต่อจากแท่งย่อยที่มีจริง สะสม H/L เดิมต่อและยังรอ Close กลับถึง Open หลัก
- ถ้าช่วงที่หายทับเวลาที่โบรกเกอร์ระบุว่ามีราคาเสนอ แม้เพียงบางส่วน จะไม่เริ่มสัญญาณเพิ่มเติมในแท่งหลักนั้น เพราะยังอาจขาด H/L ที่เกิดขึ้นจริง
- ถ้ายังอ่าน quote sessions ไม่ได้ จะใช้ข้อกำหนดเวลาเรียงต่อกันเดิม ไม่ยอมรับ gap โดยเดาเอา สถานะ lower-close แสดง `sessions OK` หรือ `sessions unavailable`
- ไม่สร้าง OHLC แท่งย่อยสมมติ ไม่อ่าน final main H/L ก่อนเวลา และไม่เปลี่ยนกฎ hunt/Open/FVG/Strong/color/swept-wick-body/frozen links
- อ่าน session ทุกวันในสัปดาห์และหลาย session ต่อวัน รองรับช่วงข้ามเที่ยงคืน รวม session จากวันก่อนหน้าเมื่อเช็ค gap ใช้ quote hours ไม่ใช่ trade permissions ผ่าน [SymbolInfoSessionQuote](https://www.mql5.com/en/docs/marketinformation/symbolinfosessionquote)
- Cache ตารางและตรวจ refresh ไม่เกินครั้งต่อนาที เมื่อมีตารางใหม่จะ replay ใหม่ เมื่อ API ขัดข้องชั่วคราวเก็บตารางที่อ่านสำเร็จก่อนหน้าไว้ ตารางที่ API ให้เป็นตารางรายสัปดาห์ปัจจุบัน ไม่ใช่ฐานประวัติวันหยุด/ตาราง DST ของทุกวันย้อนหลัง จึงยังอาจ skip ช่วงพิเศษที่ไม่ได้อยู่ในตาราง

ชื่อ indi/สถานะบอก TF, โหมด Lower close/history, จำนวน events และวันเริ่มข้อมูลย่อย

Timer 1 วินาทีช่วยตรวจว่ามีแท่งย่อยใหม่หรือไม่ แต่ไม่ใช้ราคาของแท่ง M5 ที่ยังไม่ปิดสร้างสัญญาณ ค่า Open/จำนวน bars/history เปลี่ยนจะ replay ข้อมูลปิดใหม่; การโหลดประวัติครั้งแรกไม่ส่ง Popup ไม่ใช่ tick replay หรือผลทดสอบกำไร

## โหมดเดิมที่เลือกได้

เลือก `InpObservationMode=WHA_LIVE_TICK` เพื่อใช้การยืนยันด้วย tick เดิม พร้อมการทบทวน anchor ของ v1.06 เมื่อเปิดกรองสี: รับ tick ของ symbol ที่แนบและมี timer 1 วินาทีช่วยตรวจ กลับถึง Open แล้วให้สัญญาณทันที โหมดนี้ไม่รอ TF ย่อยและไม่ใช้แท่งหลักที่ยังไม่ปิดเป็น anchor ลูกศรมีเฉพาะเหตุการณ์ที่ instance สังเกตขณะเปิดอยู่; ถอด/เปลี่ยน Inputs/TF หรือปิด MT5 จะล้างประวัติการสังเกต ไม่สร้างเหตุการณ์ก่อนแนบย้อนกลับขึ้นมา หากแนบกลางแท่งและราคา ณ ตอนแนบผ่านเงื่อนไข จะเริ่ม event ณ ตอนนั้น

เลือก `WHA_CLOSED_CANDLE` เพื่อดูย้อนหลังจากแท่งหลักที่โหลดไว้ โหมดนี้รอ **Close ของแท่ง hunt** ≥ Open สำหรับ Buy / ≤ Open สำหรับ Sell แล้วจึงตรวจ anchor โดยใช้เฉพาะแท่งก่อนหน้า ไม่มี tick replay หรือ TF ย่อย ไม่สร้างสัญญาณของแท่งที่กำลังก่อตัว และไม่แจ้ง Popup ของประวัติครั้งแรก

กฎการยืนยันสองโหมดต่างกัน: tick อาจกลับถึง Open ระหว่างแท่งแล้วปิดกลับผิดฝั่ง หรือปลายหางเปลี่ยนหลัง tick ให้สัญญาณ ดังนั้นลูกศรย้อนหลังแบบ Closed ไม่ใช่ผล replay ที่เท่ากับโหมดสด ใช้เป็นการตรวจแท่งปิดตามกฎที่ระบุ ไม่ใช่ผลทดสอบกำไร

## การวาด

รุ่น 1.02 ย่อลูกศรเป็นความหนา 1 เพิ่มระยะเป็น 200 points และวาดลูกศรในชั้นพื้นหลังเพื่อไม่บัง panel ด้านหน้า เช่น Scalp Calculator โดยเงื่อนไขสัญญาณเดิมไม่เปลี่ยน ค่า Inputs ที่บันทึกบนกราฟเก่าจะไม่เปลี่ยนอัตโนมัติ ให้โหลด preset H1/M5 ใหม่ หรือปรับ `InpArrowWidth=1` และ `InpArrowGapPoints=200` เอง

ลูกศร Buy อยู่ใต้ Low และ Sell เหนือ High ของ **แท่งบน TF กราฟที่เปิดดู** ซึ่งครอบคลุมเวลาสัญญาณ เว้นระยะด้วย `InpArrowGapPoints` และขยับตามหางแท่งสดที่ขยาย โหมด Closed วางในแท่งที่เพิ่งปิด แต่เวลาใน Tooltip/buffer เป็นเวลาปิดจริง

ตั้งแต่ 1.11 `InpShowAnchorLinks=true` วาดเส้นแนวนอนจาก **เวลาเกิดสัญญาณจริง (`e.time`) ที่ราคาปลายหาง ณ ตอนนั้น (`e.signal_tip`)** กลับไปยัง anchor ที่ยืนยันตอนเกิดสัญญาณ ตรึงเวลาและราคาไว้ ไม่ขยับเส้นเมื่อหางยืด และไม่เริ่มเส้นที่เวลาเปิดแท่ง hunt อีกต่อไป

`e.tip` ยังเป็นปลายหางล่าสุด ใช้ทบทวน anchor และยกเลิกสัญญาณตามกฎเดิม หาก event ถูกยกเลิกจะลบเส้นด้วย; หากเกิด event ใหม่จะตรึงที่เวลา/ปลายหางของ event ใหม่นั้น ดังนั้นเส้นเดิมอาจอยู่กลางหางแท่งเมื่อหางยืดภายหลัง ไม่ได้หมายถึงตรึงให้สัญญาณคงอยู่ตลอด Tooltip แสดงทั้ง signal tip และ latest tip แยกกัน ปิดเส้นได้โดยไม่เปลี่ยนการตรวจ

## Buffers / iCustom

Path `WickHuntAnchor\\WickHuntAnchor`; ค่าไม่มีสัญญาณเป็น `EMPTY_VALUE`

| Buffer | ค่า |
|---|---|
| 0 / 1 | ราคาขณะสัญญาณ Buy / Sell; ไม่ใช่ตำแหน่งวาดลูกศร |
| 2 | เวลาสังเกต tick หรือเวลาปิดยืนยัน |
| 3 | ทิศทาง +1 / −1 |
| 4 | ปลายหางล่าสุดของ event ที่ใช้ revalidation; ไม่ใช่ระดับเส้นที่ตรึง ณ เกิดสัญญาณ |
| 5 | เวลาเปิดแท่ง anchor |
| 6 | 1 FVG, 2 Strong, 3 ทั้งคู่ |
| 7 | % หางหัวของ anchor ต่อ High−Low |
| 8 | 0 tick / 1 แท่งหลักปิด / 2 แท่งย่อยปิด |

บนแท่งกราฟที่มีหลาย events ราคา Buy/Sell เก็บล่าสุดของแต่ละฝั่ง ส่วน metadata เก็บ event ล่าสุดรวมสองฝั่ง

## ติดตั้งและ preset

1. แตก `WickHuntAnchor-1.12.zip` แล้วคัดลอก `MQL5/Indicators/WickHuntAnchor` ลง Data Folder ของ MT5
2. Refresh Navigator → Indicators → WickHuntAnchor แล้วแนบบนกราฟ
3. ค่าเริ่มต้น H1/M5 ตรวจทุก M5 ปิด หรือโหลด [h1-m5.set](h1-m5.set) โดยเฉพาะเมื่อใช้ Inputs/template ของ v1.00 อยู่
   หากใช้ FVG only / Strong 20% / ลูกศร 1 และระยะ 60 points / anchor ไม่เกิน 36 แท่ง ให้โหลด [h1-m5-fvg-only.set](h1-m5-fvg-only.set)
   สำหรับโหมด OR + Buy anchor เขียว / Sell anchor แดง + Strong 20% + ลูกศร 1/60 points + anchor ไม่เกิน 36 แท่ง ใช้ [h1-m5-or-colors.set](h1-m5-or-colors.set)
4. โหมดเดิมยังเลือกได้: [m15-live.set](m15-live.set) ตรวจ tick ของ M15; [m15-history.set](m15-history.set) ตรวจ Close ของแท่งหลัก M15 ไม่ใช้ TF ย่อย
5. ตรวจชื่อ `1.12 PERIOD_H1 / PERIOD_M5 [Lower close/history]` และจำนวน signals ที่มุมล่างซ้าย โหลดประวัติทั้ง H1/M5 ให้ครอบคลุมช่วงที่จะดู
