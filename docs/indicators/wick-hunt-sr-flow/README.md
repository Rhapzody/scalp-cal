# WickHuntSRFlow 1.06

Indicator MT5 สำหรับตรวจ **TF ใหญ่ wick hunt → Close TF ย่อยยืนยันกลับถึง Open → แท่งย่อยหลังจากนั้นปิดข้าม S/R จาก MACD Swing Count โหมด Histogram → แท่งถัดไปปิดยืนฝั่งเดิม → ย้อนแตะ S/R ภายใน 8 แท่ง** ค่าเริ่มต้น H1 / M5 เปลี่ยนได้จาก Inputs ทั้งสองฝั่ง Buy/Sell ไม่ต้องรอ H1 ปิด และไม่ต้องแนบ MACDSwingCount แยก

ค่าเริ่มต้นใหม่ `InpObservationMode=WH_LOWER_TF_CLOSE` ใช้กฎแท่งปิดเดียวกันทั้งการตรวจสดและย้อนหลัง พร้อมลูกศรย้อนหลังจากประวัติที่โหลดไว้ เลือก `WH_TICK_LIVE` เพื่อใช้การตรวจราคาสดแบบ v1.04 โดยไม่มี replay สัญญาณย้อนหลัง **WickHuntTelegramEA ไม่ได้เปลี่ยนตามค่าเริ่มต้นนี้: ยังใช้ tick/reclaim/retest สดแบบเดิม** โหมด Close ของ indi อาจช้ากว่าและให้สัญญาณต่างจาก EA

ค่าเริ่มต้นรับบริบท H1 Breakout หรือ Pullback ที่อธิบายด้านล่าง แล้วจึงรอ M5 ยืนยัน ตรวจการข้ามระดับ swing ไม่ตรวจรูปทรง H&S, double bottom/top หรือ triple bottom/top เพิ่ม ไม่มีการเปิดออเดอร์หรือคำนวณ SL/TP

รุ่น 1.06 วางลูกศรที่แท่งของ **TF กราฟที่เปิดดู** ซึ่งครอบคลุมเวลาสัญญาณ: Buy อยู่ใต้ Low และ Sell อยู่เหนือ High ของแท่งนั้น เว้นระยะด้วย `InpArrowGapPoints` เมื่อแท่งสดยืดหาง ลูกศรจะขยับตามขอบแท่ง ราคาสัญญาณจริง/เวลา/metadata ใน buffers และ Tooltip คงเดิม เปลี่ยนเฉพาะตำแหน่งวาด ไม่เปลี่ยน logic หรือ EA

เวอร์ชัน **TradingView Pine v6** รวม SR กับ Anchor และแยก markers `SR` / `A`: [source](../../../Pine/Indicators/WickHuntSRAnchor.pine), [ติดตั้ง / Inputs / Alerts](pine.md), [สถานะตรวจสอบ](pine-build.md)

## สองสถานการณ์ของ TF ใหญ่

S/R ของบริบท H1 และ S/R ที่ M5 ต้องปิด break คำนวณแยกตาม TF โดยใช้ MACDSwingCount Histogram, periods/warmup/anchor เดียวกัน ไม่บังคับให้ราคา S/R สอง TF เท่ากัน

### Breakout — `WS_BREAKOUT`

1. H1 ปัจจุบันกวาด Low ของ N แท่งก่อนหน้าสำหรับ Buy / High สำหรับ Sell (`InpHuntBars=1`)
2. ใน **5 แท่ง H1 ที่ปิดก่อนแท่งปัจจุบัน** ต้องมีอย่างน้อยหนึ่งแท่งที่ `Low ≤ S/R ≤ High` แตะระดับ H1 Histogram swing ที่ยืนยันก่อนแท่งที่แตะเปิดแล้ว ไม่ต้องปิดข้าม S/R ในขั้นนี้: Bull ใช้ Swing H เป็นฝั่งต้านและ hunt หางล่าง; Bear ใช้ Swing L เป็นฝั่งรับและ hunt หางบน หน้าต่าง 5 แท่งใช้หา base ใกล้ S/R ไม่บังคับว่าฐานต้องยาว 5 แท่ง ฐาน 2 แท่งก็อยู่ในหน้าต่างนี้ได้
3. ลากเส้นจากปลายหางปัจจุบันไปทางซ้าย ตรวจทุกแท่ง: **แท่งแรกที่ High–Low ครอบคลุมปลายหาง** ต้องเป็นแท่งที่ 3 ซึ่งยืนยัน FVG ทิศเดียวกับสัญญาณ และปลายหางอยู่ใน body ของแท่งนั้น ถ้ามีแท่งอื่นบัง ไม่ข้ามไปเลือก FVG ที่ไกลกว่า
4. ความแข็งแรงใช้ `EILeadWickAllows` ของ EngulfImbalanceFlow 1.08 โดยตรง: Buy แท่งยืนยันเป็นเขียวและหางบน ≤30% ของ High–Low; Sell แท่งยืนยันเป็นแดงและหางล่าง ≤30%; doji ไม่ผ่าน
5. FVG ใช้ core เดิม: Buy `Low3 > High1`, Sell `High3 < Low1` และแท่งกลางต้องครอบคลุม gap; minimum gap เริ่มต้น 0 points, ไม่บังคับสีแท่งกลาง
6. เมื่อผ่านบริบทและกลับถึง Open จึงจำเวลา reclaim แล้วรอ M5 ปิด break ในทิศสัญญาณภายหลัง

นำกฎ FVG/ความแข็งแรง/first collision/body touch จาก flow เดิมมาใช้ ไม่เพิ่มกฎ engulf, สี engulfed หรือหางหัว engulf ≤10% ให้ hunt รอบนี้ `InpFVGSearchBars=0` ค้นทุกแท่งในประวัติ H1 ที่โหลด ไม่ใช้ค่า max gap 5 ของ flow เดิม เพราะ 5 แท่งในเงื่อนไขใหม่นี้เป็นหน้าต่าง **แตะ S/R**

### Pullback — `WS_PULLBACK`

นิยามโครงสร้างที่ใช้ในโค้ด:

- Buy: Swing L ยืนยันแล้ว → H1 **ปิดข้ามขึ้นเหนือ S/R ของ Swing H** ที่รู้ก่อนแท่ง breakout เปิด → ยืนยัน Swing H ปลายทางที่ pivot อยู่บน/หลังแท่ง breakout → ราคาย่อลง → H1 ปัจจุบันกวาด **Low ของสอง H1 ก่อนหน้า** แล้วกลับถึง Open → M5 ปิด break ขึ้น
- Sell: Swing H ยืนยันแล้ว → H1 ปิดข้ามลงใต้ S/R ของ Swing L → ยืนยัน Swing L ปลายทาง → ราคาเด้งขึ้น → H1 ปัจจุบันกวาด **High ของสอง H1 ก่อนหน้า** แล้วกลับถึง Open → M5 ปิด break ลง

H1 ปัจจุบันหนึ่งแท่งต้องมี Low ต่ำกว่าทั้งสอง Low / High สูงกว่าทั้งสอง High อย่างเคร่งครัด ไม่ใช่ hunt หางบนและล่าง และไม่ใช้สองแท่ง hunt แยกกัน จำนวนหางปรับด้วย `InpPullbackHuntBars` เริ่มต้น 2 และอย่างน้อย 2

โครงสร้างอิง H1 ที่ปิดและ swing ที่ยืนยันแล้ว ไม่อนุมานจากสี MACD เมื่อ H1 ปิด break โครงสร้างในทิศตรงข้ามจะเปลี่ยนบริบทและต้องรอ swing ปลายทางใหม่ ส่วน **H1 แท่งที่กำลัง hunt ไม่ต้องรอปิด** ก่อน reclaim/M5 confirmation

Pullback ไม่เพิ่มเงื่อนไข 5-bar touch/FVG ซึ่งเป็นตัวกรองของ Breakout `WS_BOTH` หมายถึงผ่าน Breakout **หรือ** Pullback หากผ่านทั้งคู่ตอน reclaim ให้หนึ่ง event ต่อฝั่งพร้อม tag `3 = both` ไม่ใช่สองสัญญาณซ้ำ บริบทและข้อมูล FVG/swing จะถูกจำ ณ เวลา reclaim ครั้งแรก ไม่ยกผลคำนวณใหม่มารับ M5 break ที่ปิดก่อน reclaim

## Buy / Sell

| เงื่อนไข | Buy | Sell |
|---|---|---|
| Hunt ของแท่ง TF ใหญ่ปัจจุบัน | Low ต่ำกว่า Low ต่ำสุดของ N แท่งก่อนหน้า และต่ำกว่า Open ของตัวเอง | High สูงกว่า High สูงสุดของ N แท่งก่อนหน้า และสูงกว่า Open ของตัวเอง |
| กลับถึง Open (โหมด Close) | Close TF ย่อย ≥ Open ของแท่ง TF ใหญ่ | Close TF ย่อย ≤ Open ของแท่ง TF ใหญ่ |
| TF เล็กปิดข้ามระดับ S/R | Close ก่อนหน้า ≤ S/R และ Close ล่าสุด > S/R | Close ก่อนหน้า ≥ S/R และ Close ล่าสุด < S/R |
| แท่งถัดไปยืนยัน | Close > S/R เดิม | Close < S/R เดิม |
| สัญญาณ retest (ค่าเริ่มต้นโหมด Close) | Low ของแท่งรอแตะหรือข้ามลงถึง S/R เดิม แล้วรอแท่งนั้นปิด | High ของแท่งรอแตะหรือข้ามขึ้นถึง S/R เดิม แล้วรอแท่งนั้นปิด |

- Breakout/Legacy ใช้ `InpHuntBars=1`; Pullback ใช้ `InpPullbackHuntBars=2` แยกกัน; N มากกว่า 1 ต้องกวาดขอบสุดของทุกแท่งในช่วงนั้น ไม่นับแท่ง TF ใหญ่ปัจจุบัน
- การแตะ Low/High เดิมพอดีไม่ผ่าน hunt; การกลับถึง Open พอดีผ่าน
- Close ล่าสุดเท่ากับ S/R ไม่ผ่าน breakout; ไส้ทะลุแต่ปิดกลับเข้ามาไม่ผ่าน
- ระดับ **ของ TF เล็ก** จาก Swing H และ Swing L ใช้ได้ทั้งสองทิศ เช่น Buy ได้จากการ reclaim Swing L หรือทะลุ Swing H ขึ้น
- ต้องสังเกต TF ใหญ่ hunt และกลับถึง Open **ก่อน** แล้วจึงเริ่มรับ TF เล็กที่ปิดข้าม S/R เวลา Close ต้องหลัง reclaim อย่างเคร่งครัด ภายในแท่ง TF ใหญ่เดียวกัน ไม่ใช้ breakout ที่ปิดไปก่อนหรือปิดตรงเวลา reclaim
- โหมด Close: แท่งที่ยืนยัน reclaim ไม่นับเป็น breakout ด้วย ต้องเป็น Close ของแท่งหลังจากนั้น โหมด Tick เดิมอนุญาตแท่งที่เปิดก่อน reclaim หาก Close เกิดหลัง reclaim
- จำ reclaim จนสิ้นแท่ง TF ใหญ่; TF เล็กตรึง S/R ของการข้ามครั้งแรก รอ **แท่งถัดไปทันที** ปิดเหนือเส้นสำหรับ Buy/ใต้เส้นสำหรับ Sell (ค่าเริ่มต้น `InpConfirmBars=1`; เพิ่มได้เพื่อให้ทุกแท่งถัดไปติดต่อกันยืนยันครบจำนวน) ถ้าปิดเท่าเส้นหรือผิดฝั่ง หรือแท่งถัดไปหาย จะทิ้ง candidate นี้ การปิดข้ามใหม่ภายหลังจึงเริ่มชุดใหม่ได้
- หลังแท่งยืนยันสุดท้ายปิด นับ 8 แท่งถัดไป (`InpRetestBars=8`): โหมด Close ตรวจเฉพาะแท่งรอที่ปิดแล้ว โดยใช้ H/L แตะ S/R หรือเลือกใช้ Close ด้วย `InpClosedRetest` ไม่ใช้หางของแท่ง breakout/hold เป็น retest รับแท่งที่ 8 ซึ่งปิดตรง deadline ได้ แต่ไม่รับแท่งที่ 9 โหมด Tick เดิมยังใช้ราคาแตะจริงทันที ไม่อนุมานจาก H/L
- ระหว่างรอไม่เปลี่ยนเส้นอ้างอิงแม้มี swing ใหม่หรือระดับเก่าหลุดรายการล่าสุด; ถ้าไม่ย้อนแตะในกำหนด ทิ้ง candidate แล้วรอการปิดข้ามชุดใหม่ ไม่รับ retest ย้อนหลัง
- เมื่อครบ break → hold → retest ให้สัญญาณครั้งเดียวต่อฝั่งต่อแท่ง TF ใหญ่ จากนั้นราคาเคลื่อนต่อไม่ลบสัญญาณนั้น เริ่มแท่ง TF ใหญ่ใหม่จะล้าง setup ที่ยังไม่ครบ
- ไม่มีการยก breakout จากแท่ง TF ใหญ่ก่อนหน้ามาใช้ Reclaim/direct breakout ที่ปิดตรงจบแท่งใหญ่ไม่เริ่มสัญญาณใหม่ แต่โหมด Close อนุญาตยืนยัน retest ของแท่งรอสุดท้ายที่อยู่ครบภายในแท่งใหญ่เดิม ณ เวลามันปิด ลูกศรอยู่ในแท่งที่เพิ่งปิด ไม่ต่ออายุ setup ไปแท่งใหม่
- ถ้าแท่ง TF เล็กปิดข้ามหลายระดับพร้อมกัน ใช้ swing ที่ยืนยันล่าสุดในกลุ่มที่ถูกข้ามเป็นระดับอ้างอิง

ตัวอย่างลำดับ reclaim/M5 ของ **โหมด Tick เดิม** หลังผ่านบริบทที่เลือกแล้ว: H1 เปิด 100, ขอบ Low ที่ต้องกวาด = 90:

1. H1 ปัจจุบันลงถึง 89 แล้วเวลา 10:17:20 ราคากลับถึง 100 จึงเริ่มตรวจ M5
2. เวลา 10:20 M5 10:15–10:20 ปิดจาก Close ก่อนหน้า 99 เป็น 102 ผ่าน S/R ของ Swing H ที่ 101 ซึ่งยืนยันไว้แล้ว
3. M5 10:20–10:25 ต้องปิด >101 อีกครั้ง ถ้าปิด ≤101 ให้ทิ้งชุดนี้
4. เริ่มรอจากแท่ง 10:25–10:30 จนถึงแท่งที่ 8 คือ 11:00–11:05 แต่ setup H1 นี้จบ 11:00 จึงหมดอายุก่อน หากราคาสดกลับแตะ 101 เวลา 10:32 ให้ Buy ตอนนั้น โดยไม่ต้องรอ M5 หรือ H1 ปิด

หาก M5 เคยปิดข้าม S/R เวลา 10:15 ก่อน reclaim 10:17:20 จะไม่นับการข้ามเก่านั้น ต้องมีการปิดข้ามครั้งใหม่หลัง reclaim จึงให้สัญญาณ ทั้ง Buy/Sell ใช้ลำดับเดียวกัน

## ตรวจหลาย TF ขณะเปิดกราฟ H1

อ่านข้อมูล `_Symbol` แยกจาก TF ของกราฟด้วย [CopyRates ของ MT5](https://www.mql5.com/en/docs/series/copyrates) ทุก tick ตรวจราคาล่าสุดของแท่ง TF ใหญ่ ส่วน M5 swing/SR คำนวณใหม่เมื่อ M5 ขึ้นแท่งใหม่ และ H1 context คำนวณใหม่เมื่อ H1 ใหม่/ประวัติเพิ่ม จึงตรวจ M5 ต่อเนื่องได้ระหว่าง H1 ยังเปิด

ใช้ [OnTimer](https://www.mql5.com/en/docs/event_handlers/ontimer) ทุก 1 วินาทีเพื่ออ่านข้อมูลและลองใหม่เมื่อ series กำลังโหลด ไม่ใช้เวลาที่ผ่านไปอย่างเดียวเป็นหลักฐานว่าแท่งปิด ต้องมีแท่ง TF เล็กใหม่จาก MT5 ก่อนจึงประมวลผลแท่งเก่าเป็นแท่งปิด หากไม่มี quote ใหม่จะไม่มีการสมมติว่าราคาได้กลับถึง Open

ใช้ราคา Bid สำหรับกราฟ Bid และ Last สำหรับ symbol ที่ใช้กราฟ Last; ไม่ใช้ Ask เพื่อเทียบกับ Open ของกราฟ เมื่อหลุดการเชื่อมต่อ, series ยังไม่ synchronized หรือเวลาของ quote ไม่อยู่ในแท่งปัจจุบัน จะยังไม่สร้างสัญญาณใหม่

## S/R และเวลาที่รู้ swing

ใช้ `SwingCore.mqh` ที่เหมือนกับ MACDSwingCount 1.20 แบบ byte-for-byte ตั้ง `MS_HISTOGRAM_COLOR` ภายในเสมอ: EMA 12/26, Signal EMA 9 จาก Close, warmup อัตโนมัติ 34 แท่งตามค่าเริ่มต้น และกฎ Histogram เพิ่ม/ไม่เพิ่มเดียวกับตัวเดิม

- `InpSRCount=10` ใช้ swing ที่ยืนยันล่าสุดรวม High และ Low 10 จุดต่อ TF ไม่ใช่ 10 จุดต่อฝั่ง
- Wick: High/Low ของแท่ง swing จริง; Body: ขอบเนื้อของแท่ง swing จริง
- ประมวลผลแท่งปิดเรียงจากเก่าไปใหม่ ตรวจ breakout กับระดับที่ทราบก่อนแท่ง breakout เปิด แล้วค่อยเพิ่ม swing ที่แท่งนั้นเพิ่งยืนยัน จึงไม่ใช้ swing ที่เติมย้อนหลังหรือ swing ใหม่ในแท่งเดียวกันมาสร้าง breakout ของตัวเอง
- เส้นวาดจากแท่งยอด/ก้น แต่เพิ่งมีระดับเมื่อ swing ยืนยันแล้วตามกติกา MACDSwingCount
- ค่าเริ่มต้น `InpHistoryBars=0` ใช้ประวัติ TF เล็กทั้งหมดที่ MT5 โหลดไว้ เพื่อใช้ seed จากต้นข้อมูลเช่นเดียวกับ MACDSwingCount หากจำกัดประวัติหรือกราฟสองตัวโหลดประวัติไม่เท่ากัน EMA/swing อาจต่างกัน ต้องเทียบด้วย symbol, TF, periods, warmup, anchor และต้นประวัติเดียวกัน
- H1 ใช้ `InpContextHistoryBars=0` เพื่อ seed จากประวัติ H1 ทั้งหมดแยกจาก M5 ต้องเทียบต้นข้อมูลแต่ละ TF ให้ตรงกัน
- จำนวน S/R มีผลต่อระดับที่ตรวจจริง การปิด `InpShowSR` / `InpShowContextSR` ซ่อนเส้นอย่างเดียว ไม่หยุดตรวจ เส้น M5 ทึบและเส้น H1 ประ; tooltip ระบุ TF

## สัญญาณสดและประวัติ

### โหมด Close — ค่าเริ่มต้นของ indi 1.05

Replay แท่ง TF ย่อยที่ปิดเรียงจากเก่าไปใหม่ ใช้ Open TF ใหญ่ที่รู้ตอนเปิด และสะสม H/L จากแท่งย่อยที่ปิดไปแล้วเท่านั้น ไม่ใช้ H/L สุดท้ายของแท่งใหญ่ที่ยังไม่จบ ณ เวลานั้น Swing/โครงสร้าง/FVG ของ TF ใหญ่ใช้เฉพาะแท่งที่ปิดก่อนแท่งย่อยกำลังตรวจเปิด

ตัวอย่าง Buy 15m/1m: Low สะสมของ M15 กวาดครบเงื่อนไข → M1 ปิด ≥ Open M15 ยืนยัน reclaim → M1 หลังจากนั้นปิดข้าม SR → M1 ถัดไปปิดยืนเหนือ SR → แท่งรอหลัง hold แตะ SR → ยืนยันลูกศรเมื่อแท่งรอนั้นปิด Sell กลับด้าน ไม่รอให้แท่ง M15 ปิดก่อนตรวจ

`InpClosedRetest=WH_RETEST_HIGH_LOW` รับหางของแท่งรอแตะ SR ไม่ต้อง Close ทะลุกลับ เลือก `WH_RETEST_CLOSE` หากต้องการให้ Close กลับถึง SR ด้วย ราคาใน event แบบ H/L เป็นราคาอ้างอิงที่ SR ± tolerance หรือ Open ของแท่งรอหากเปิดข้ามไปแล้ว ไม่ใช่ tick/fill ที่ replay ได้จริง ไม่มีการเพิ่มเงื่อนไขให้ Close กลับไปฝั่ง breakout อีกครั้ง

ลูกศรและ buffers ผูกกับแท่งกราฟที่ครอบคลุมแท่งย่อยที่เพิ่งปิด Tooltip และ buffer 2 ระบุเวลาปิดยืนยันจริง หนึ่ง event ต่อฝั่งต่อแท่งใหญ่ แท่งใหญ่ที่มีประวัติย่อยไม่ครบตั้งแต่เปิดหรือมีช่องว่างระหว่างแท่งย่อยจะไม่สร้างสัญญาณจนถึงแท่งใหญ่ใหม่ที่ข้อมูลครบ เพื่อไม่เดาหางจากข้อมูลบางส่วน

การแนบใหม่/เปลี่ยน Inputs/เปิด MT5 ใหม่สร้างลูกศรย้อนหลังคืนได้จากแท่งราคาโดยไม่ต้องมี tick ใช้ประวัติ **TF ย่อยและ TF ใหญ่ที่ MT5 โหลดไว้** เท่านั้น เลื่อน M15 ย้อนหลังอย่างเดียวไม่ได้รับประกันว่า M1 ช่วงเดียวกันโหลดแล้ว ถ้าข้อมูลไม่พอให้เปิดกราฟ M1 โหลดช่วงนั้น และเพิ่ม Max bars in chart ตามต้องการ สถานะด้านล่างซ้ายบอกจำนวน events และวันเริ่มข้อมูลย่อยที่ replay ค่า `InpVisibleSignals=100` วาดเฉพาะ 100 events ล่าสุด; เพิ่มได้ถึง 5000 เพื่อดูช่วงเก่ากว่า

โหมดนี้ทำงานจากแท่งที่โหลดไว้ได้แม้ไม่มี quote ใหม่ ไม่ใช้แท่งย่อยที่กำลังก่อตัว และไม่แจ้ง Popup สำหรับ replay ครั้งแรก/ประวัติเก่าที่เพิ่งโหลด ไม่ใช่ผลย้อนหลังของ EA แบบ tick หรือรายงานกำไร

### โหมด Tick — `InpObservationMode=WH_TICK_LIVE`

คงพฤติกรรม v1.04: สังเกต hunt/reclaim จากราคาสด แล้วรับ breakout ที่ปิดภายหลังและ retest จาก quote จริง ไม่สร้างลูกศรย้อนหลังของแท่งใหญ่ที่จบไปแล้ว ตอนแนบกลางแท่งเริ่มจำ reclaim ณ ตอนนั้นเท่านั้น ไม่ยกเหตุการณ์ก่อนแนบกลับมาใช้

สัญญาณอยู่ในหน่วยความจำของ instance; ถอด indicator/เปลี่ยน Inputs หรือ TF จน reinitialize/ปิด terminal จะล้างประวัติที่สังเกต ไม่มี tick replay หรือบันทึกลงไฟล์ในโหมดนี้ การเปิดโหมด Tick ของ indi ไม่เปลี่ยนการตั้งค่าหรือโค้ดของ EA

| `InpContextHistoryBars` | 0 | ประวัติ H1 ทั้งหมด หรือ 100–100000 ต้องพอสำหรับ warmup/หน้าต่างที่เลือก |

Inputs ใหม่ของ v1.04 ใช้ค่าเริ่มต้นตรงกับกฎ v1.03: ยืนยัน 1 แท่ง, รอ retest 8 แท่ง, ระยะเผื่อทั้งสามเป็น 0, หางนำ FVG ไม่เกิน 30%, เปิดทั้ง Buy/Sell ส่วน TF/MACD/SR/หน้าต่างแตะ SR/จำนวนหาง/ช่วงค้น FVG/สีและแจ้งเตือนปรับได้จาก Inputs เดิม

- `InpConfirmBars=2` คือแท่ง break → ยืนยันแท่งที่ 1 → ยืนยันแท่งที่ 2 → เริ่มนับ `InpRetestBars`; ทุก Close ต้องอยู่ฝั่งถูกต้องและผ่าน buffer ถ้าแท่งใดไม่ผ่านหรือขาดหายให้ทิ้งชุดนั้น
- `InpCloseBufferPoints` ใช้เกณฑ์มากกว่าอย่างเคร่งครัด: Buy ต้อง Close > SR + ระยะ, Sell ต้อง Close < SR − ระยะ และแท่ง break ยังต้องข้ามเส้น SR จริงจาก Close ก่อนหน้า ไม่ใช่แค่ขยายระยะขณะอยู่ฝั่งเดิม
- `InpRetestTolerancePoints` เป็นระยะยอมให้เข้าใกล้: Buy ≤ SR + ระยะ, Sell ≥ SR − ระยะ; ใช้ quote ในโหมด Tick หรือ H/L/Close ตามโหมด Close และไม่ได้จำกัดความลึกที่ข้ามกลับ
- `InpMinHuntPoints` เทียบขอบสุดของแท่งก่อนหน้าที่กำหนด; Pullback ยังคงต้องกวาดครบอย่างน้อยสองหางตามเทรน และกลับถึง Open จริง
- `InpFVGMaxLeadWickPercent` Buy วัดหางบน ส่วน Sell วัดหางล่าง; ค่าน้อยเข้มงวดขึ้น ยังคงบังคับสีแท่ง, FVG ทิศเดียวกัน, first collision และ tip อยู่ใน body
- ทุกขั้นตอนยังต้องจบภายในแท่ง TF ใหญ่เดียวกัน การเพิ่มจำนวนแท่งยืนยัน/รอไม่ได้ต่ออายุ setup ข้ามแท่งใหญ่
- หน่วย points อิง `_Point` ของ symbol ใน MT5 เช่นทองที่ `_Point=0.01`: 10 points = 0.10 ของราคา

TF ใหญ่ต้องมากกว่า TF เล็ก, มีระยะหารลงตัว, ระบุ TF ตายตัว ไม่ใช้ `PERIOD_CURRENT` และ TF ใหญ่ไม่เกิน D1 จึงไม่รองรับ W1/MN1 ในรุ่นนี้ แนบกับกราฟเวลา MT5 ไม่เกิน D1 โดยแนะนำกราฟ TF ใหญ่หรือ TF เล็กที่เลือก

## Buffers / iCustom

| 11 | เวลาเปิดแท่ง pivot ของ swing ปลายทางใน Pullback; ไม่มีเป็น EMPTY_VALUE |

Inputs v1.04 ทั้ง 7 รายการต่อท้าย `InpRetestBars` และ v1.05 เพิ่มสอง Inputs ใหม่ท้ายสุดเพื่อรักษาลำดับ positional iCustom เดิม buffers 0–11 ยังใช้ตำแหน่งเดิม แต่ค่าเริ่มต้นเปลี่ยนเป็นโหมด Close ผู้เรียก iCustom ที่ต้องการพฤติกรรม tick ต้องระบุ `WH_TICK_LIVE` ด้วย; `WS_LEGACY` และ `InpRetestBars=0` เลือกกฎเดิม v1.01 แต่ไม่เลือกวิธี observation แทน Input ใหม่

วางค่าในแท่ง **ของกราฟที่แนบ** ซึ่งครอบคลุมเวลาสัญญาณ บน H1 จึงมีค่า shift 0 ได้เมื่อ H1 ยังไม่ปิด ค่านี้เป็น event ที่สังเกตและยืนยันแล้ว ไม่ใช่ preview ที่ต้องรอปิด H1

กรณีกราฟหนึ่งแท่งครอบคลุมหลายสัญญาณ buffers 0/1 เก็บราคาล่าสุดของแต่ละฝั่ง ส่วน buffers 2–11 เก็บ metadata ของ event ล่าสุดรวมสองฝั่ง ลูกศรแต่ละ event ยังแยกกันตามเวลายืนยัน ผู้เรียก iCustom ควรใช้ `(เวลา TF ใหญ่, ทิศทาง)` เพื่อกันทำซ้ำ และตรวจ `CopyBuffer` สำเร็จ/ค่าไม่ใช่ `EMPTY_VALUE` WickHuntTelegramEA ใช้ shared cores โดยตรง จึงไม่ได้อ่านค่าเริ่มต้นของ indi นี้

## ติดตั้ง

1. แตก `WickHuntSRFlow-1.06.zip`
2. คัดลอกโฟลเดอร์ `MQL5/Indicators/WickHuntSRFlow` ลง Data Folder ของ MT5 ใต้ `MQL5/Indicators`
3. Refresh Navigator แล้วลาก WickHuntSRFlow ลงกราฟ H1
4. เริ่มด้วย `InpHuntTF=PERIOD_H1`, `InpSignalTF=PERIOD_M5`, `InpScenario=WS_BOTH`, `InpTouchBars=5`, `InpHuntBars=1`, `InpPullbackHuntBars=2`, `InpSRAnchor=MS_SR_WICK`
5. รอข้อมูลสอง TF synchronized ดูสถานะด้านล่างซ้าย และเปิด M5 คู่กันเพื่อตรวจระดับ/แท่ง breakout

สำหรับทอง 15m/1m ตั้ง `InpHuntTF=PERIOD_M15`, `InpSignalTF=PERIOD_M1`, `InpObservationMode=WH_LOWER_TF_CLOSE` หรือโหลด [m15-m1-history.set](m15-m1-history.set) จากปุ่ม Load ในหน้า Inputs TF กราฟไม่เปลี่ยนสอง Inputs นี้อัตโนมัติ preset วาดได้ถึง 5000 ลูกศรตามประวัติที่โหลด

แต่ละ instance มีชื่อ object ของตนเอง ถอดแล้วลบเฉพาะ object ของตัวเอง ไม่มี dependency กับไฟล์ EX5 ของ MACDSwingCount
