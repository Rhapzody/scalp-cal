# ตรวจการทำงาน Engulf Flow / Imbalance Flow

ตรวจ source ในโปรเจควันที่ 27 กันยายน 2026: EngulfFlow 1.05 และ ImbalanceFlow 1.11 ใช้ symbol/timeframe ของกราฟที่ติดตั้ง ทั้งสองเป็น indicator ไม่ส่งคำสั่งซื้อขาย และไม่ได้กำหนด entry, SL, TP หรือขนาด position ให้เป็นกลยุทธ์ครบชุด

## Engulf Flow: ลูกศรจากการปิดทะลุร่วมกับการกวาดไส้

ค่าเริ่มต้น: BODY engulf, Hunt 1 แท่ง, ปิด Prior Move และ EMA filter

เรียกแท่งสัญญาณว่า A และแท่งก่อนหน้าทันทีว่า B:

| เงื่อนไขเริ่มต้น | ลูกศร Buy | ลูกศร Sell |
|---|---|---|
| ปิดพ้นเนื้อ B | Close A > max(Open B, Close B) | Close A < min(Open B, Close B) |
| กวาดไส้ B | Low A < Low B | High A > High B |
| มีไส้ฝั่งที่กวาดจริง | Low A < min(Open A, Close A) | High A > max(Open A, Close A) |

ต้องผ่านทุกข้อและต้องทะลุจริง ไม่รวมแตะเท่ากัน ไม่บังคับสี A/B และไม่บังคับราคาเปิด A ให้ครอบเนื้อ B จึงไม่ใช่นิยาม engulfing แบบครอบทั้ง body ที่บางคนคุ้นเคย ชื่อ Flow ใช้ได้ทั้งจังหวะกลับตัวและย่อแล้วไปต่อ แต่ตัวโค้ดไม่ได้ติดป้ายจำแนกสองกรณีนี้

ตัวเลือกเพิ่มเติม:

- WICK mode เปลี่ยนเงื่อนไขราคาปิดเป็น Close A > High B หรือ Close A < Low B; ไส้ทะลุอย่างเดียวไม่พอ
- Hunt = 0 ปิดข้อกำหนดกวาดไส้และการมีไส้ฝั่งนั้น; Hunt = N ต้องกวาดครบ N แท่งก่อนหน้า แต่ engulf ยังเทียบ B แท่งเดียว
- Prior Move ต้องมีช่วงสวนทางก่อน A อย่างน้อย 3 แท่งตามค่าเริ่มต้นของจำนวนแท่ง นับช่วงด้วย BODY engulf ไม่ใช่นับแท่งสีเดียวติดกัน inside bar / doji / แท่งสีสวนอาจยังนับต่อได้
- EMA filter อนุญาต Buy เมื่อ EMA20 > EMA54 และ Sell เมื่อ EMA20 < EMA54; เท่ากันไม่ให้สัญญาณ รอข้อมูลครบ 54 closes ใช้ EMA ที่แท่งสัญญาณ ไม่บังคับราคาต้องอยู่เหนือ/ใต้เส้น และไม่ต้องเกิด crossover

การแสดงผล:

- Buy เป็นลูกศร LimeGreen ใต้ Low; Sell เป็นลูกศร Red เหนือ High ระยะห่าง 10 pixels ความหนา 2
- ก่อน 5 วินาทีสุดท้ายของแท่งปัจจุบันไม่มีลูกศร จากนั้นใช้ Close ล่าสุดประเมิน preview ซึ่งหายหรือกลับมาได้
- เมื่อมีแท่งใหม่ ตรวจแท่งเดิมซ้ำด้วย OHLC สุดท้าย ผ่านจึงเก็บลูกศร แม้ไม่เคยขึ้น preview ก็เกิดลูกศรยืนยันได้
- Timer ทุก 1 วินาทีช่วยเปิด preview เมื่อไม่มี tick ใหม่ แต่ timer อย่างเดียวไม่ยืนยันราคาปิด ต้องรอ MT5 ส่งแท่งใหม่
- ย้อนหลังคำนวณจากแท่งปิดทั้งหมดที่มีข้อมูลรองรับ ไม่จำกัด 500 แท่งแบบ Imbalance
- EMA คำนวณภายใน ไม่มีเส้น EMA เพิ่มบนกราฟ ไม่มีเส้น entry/SL/TP
- Buffer 0 เป็น Low ของสัญญาณ Buy, buffer 1 เป็น High ของ Sell; shift 0 ยังเปลี่ยนได้

อ่าน source: `MQL5/Indicators/EngulfFlow/EngulfFlowCore.mqh` (`WHEngulfDirection`, `WHSignal`, `WHStepLeg`) และ `EngulfFlow.mq5` (`WHSignalAt`, `WHRefreshLive`, `OnCalculate`)

## Imbalance Flow: กล่อง FVG และ Displacement

ค่าเริ่มต้นตรวจทั้งสองชนิดจากแท่งปิด ไม่สร้าง preview บนแท่งกำลังก่อตัว ไม่ได้อ่าน order book หรือ order flow จริง เกณฑ์ทั้งหมดมาจาก OHLC

### FVG: รูปแบบ 3 แท่ง

เรียง 1 → 2 → 3 จากเก่าไปใหม่:

- Bullish: Low ของแท่ง 3 > High ของแท่ง 1; กล่องอยู่ระหว่างราคาทั้งสอง
- Bearish: High ของแท่ง 3 < Low ของแท่ง 1; กล่องอยู่ระหว่างราคาทั้งสอง
- High/Low ของแท่งกลางต้องครอบคลุมช่องว่างทั้งหมด แค่ session gap ที่แท่งกลางไม่เคยผ่านโซนไม่พอ
- แตะพอดีไม่นับ gap ค่าเริ่มต้น MinGapPoints = 0 และไม่บังคับสีแท่งกลาง ไม่มี ATR/body filter สำหรับ FVG

### Displacement: แรงส่งแม้ไม่มี FVG

ลองแท่งเดี่ยวก่อน ถ้าไม่ผ่านค่อยลองขา 2, 3, 4 แท่ง เลือกขาที่สั้นที่สุดที่ผ่าน ค่าเริ่มต้น:

| เกณฑ์ | แท่งเดี่ยว | ขา 2–4 แท่ง |
|---|---|---|
| ขนาดแรงส่ง | Body ≥ 0.80 × ATR ก่อนขา | ระยะ Close สุดท้ายจาก Close ก่อนขา ≥ 1.50 × ATR ก่อนขา |
| ความชัดของทิศ | Body / Range ≥ 70% | ระยะสุทธิ / ผลรวมระยะ Close-to-Close ≥ 75% |
| แท่งไปตามทิศ | เนื้อแท่งต้องตามทิศ | ≥ 66% ของจำนวนแท่ง และแท่งสุดท้ายต้องตามทิศ |
| ไส้ด้านปลายทาง | ≤ 15% ของ Range | ≤ 20% ของ Range แท่งสุดท้าย |

ทั้งคู่ต้องปิดทะลุกรอบ High/Low ของ 5 แท่งก่อนเริ่มขาอีกมากกว่า 0.10 × ATR; ATR เป็นค่าเฉลี่ยเลขคณิตของ True Range 14 แท่งก่อนขา ไม่ใช่ Wilder ATR และไม่รวมแรงส่งเข้าไปในฐานเปรียบเทียบ

ค่าเริ่มต้น RejectTimeGaps = true จึงต้องมีเวลาต่อเนื่องในช่วงอ้างอิงและขาแรงส่ง ช่องว่างช่วงปิดตลาดหรือข้อมูลขาดอาจทำให้ไม่ผ่าน ส่วน RelativeBody filter ปิดอยู่

กล่องเริ่มต้นใช้ High/Low ของแท่งสวนทางหรือ doji ล่าสุดก่อนขา โดยค้นย้อนหลังไม่เกิน 5 แท่ง ถ้าไม่พบใช้แท่งก่อนขา ต้องปิดออกจากกล่องแล้วจึงยืนยัน เปลี่ยนได้เป็น body ของแท่งต้นทางหรือ body ของขา แต่ละต้นทาง/ทิศสร้าง Displacement ครั้งเดียวภายใน lookback ที่กำลังสแกน

### สิ่งที่เห็นบนกราฟและเหตุผลที่กล่องหาย

| ประเภท | ขึ้น | ลง |
|---|---|---|
| FVG | DarkGreen ขอบหนา 1 | Maroon ขอบหนา 1 |
| Displacement | Teal ขอบหนา 2 | DarkOrange ขอบหนา 2 |
| เติมแล้ว เมื่อเปิด ShowFilled | DimGray | DimGray |

กล่องระบายสีอยู่หลังแท่งเทียน ชี้ที่ขอบกล่องมี tooltip ระบุชนิด ทิศ ราคา และเวลาเปิดของแท่งสัญญาณ

- FVG ยืนยันหลังแท่ง 3 ปิด; Displacement ยืนยันหลังแท่งสุดท้ายของแรงส่งปิด แม้กล่องจะวาดเริ่มย้อนกลับไปที่แท่งต้นทาง ห้ามถือว่าเข้าถึงสัญญาณได้ตั้งแต่ต้นกล่อง
- ค่าเริ่มต้น FULL: Bullish เติมเมื่อ Low ของแท่งหลังยืนยันลงถึงขอบล่าง; Bearish เติมเมื่อ High ขึ้นถึงขอบบน แตะพอดีนับและใช้เฉพาะแท่งปิด
- TOUCH เปลี่ยนเป็นแตะขอบใกล้; FULL ที่เติมบางส่วนไม่ย่อขอบกล่อง
- ShowFilled = false จึงซ่อนกล่องเมื่อเติมครบ ถ้าเปิดจะแสดงสีเทาและหยุดที่ปลายแท่งแรกที่เติมครบ
- กล่อง active ยืดถึงเวลาเปิดแท่งปัจจุบัน + 10 ช่วงเวลาแท่ง
- Lookback = 500 แท่งปิด, MaxZones = 50 กล่องรวมทั้งสองชนิด เลือกที่ใหม่ก่อน FVG ได้สิทธิ์ก่อนเมื่อเกิดพร้อมกัน
- กล่องอาจหายเพราะเติมแล้ว, เกิน lookback หรือถูกจำกัดจำนวน ไม่ได้แปลว่าการตรวจสัญญาณเดิมผิด
- การสแกนใหม่เมื่อหน้าต่าง lookback เลื่อนอาจเปลี่ยน Displacement เก่าที่ถูกเลือก เพราะการกันซ้ำใช้ต้นทางภายในหน้าต่างนั้น
- Buffers 0–2 เก็บทิศ/ขอบ FVG, 3–6 เก็บทิศ/ขอบ/ชนิด Displacement ที่แท่งยืนยัน ไม่ใช่รายการโซน active: เติมแล้วก็ยังมี buffer ตราบที่อยู่ใน lookback และไม่มี buffer สถานะ fill

อ่าน source: `MQL5/Indicators/ImbalanceFlow/FVGCore.mqh`, `DisplacementCore.mqh` และ `ImbalanceFlow.mq5` (`RebuildFVG`, `DrawFVGZone`, `OnCalculate`)

## ผลตรวจและขอบเขตการทดสอบ

รันคำสั่งกับ source ปัจจุบันสำเร็จ:

```text
sh scripts/test.sh engulf-flow       → 21,019 checks passed
sh scripts/test.sh imbalance-flow    → 5,043 checks passed
```

เป็น C++ tests ที่ใช้ core และดึง body ฟังก์ชันจาก MQL5 มาจำลอง API ของ MT5 ครอบคลุมการตรวจสัญญาณ ขอบเขตราคา preview/ยืนยัน buffers การเติม และการคำนวณใหม่ ไม่ใช่ผลเทรดและไม่ยืนยันภาพ native MT5

ตรวจไฟล์ `.mq5` / `.mqh` เทียบแพ็กเกจ `dist/indicators/engulf-flow/EngulfFlow-1.05.zip` และ `dist/indicators/imbalance-flow/ImbalanceFlow-1.11.zip` แล้วตรงกันทุกไฟล์ ดังนั้นคำอธิบายนี้ตรงกับ source ที่บรรจุใน ZIP ของโปรเจคด้วย

การทดสอบย้อนหลังด้วย H1 OHLC ตรวจลูกศรหลังแท่งปิดและการเกิด/เติมโซนได้ แต่ยืนยันลำดับ tick หรือ preview 5 วินาทีไม่ได้ หากต้องการ win rate ของการเทรด ต้องระบุกติกาเข้าออก ต้นทุน และการจัดการสัญญาณซ้อนเพิ่มก่อน ทั้งสอง indicator ไม่ได้กำหนดสิ่งเหล่านั้นเอง
